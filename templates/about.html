ℹ️ Acerca del Laboratorio XSS

Sistema educativo para aprender sobre vulnerabilidades Cross-Site Scripting

📚 ¿Qué es este Laboratorio?

Este es un entorno de aprendizaje INTENCIONALMENTE VULNERABLE diseñado para enseñar sobre vulnerabilidades XSS (Cross-Site Scripting) de forma práctica y segura.

Los estudiantes pueden experimentar con diferentes tipos de ataques XSS sin riesgo de dañar sistemas reales, aprendiendo tanto las técnicas de explotación como las mejores prácticas de defensa.

🎯 Ejercicios Disponibles

1. Reflected XSS

  • Nivel: Principiante
  • Objetivo: Ejecutar JavaScript reflejado en la respuesta
  • Aprenderás: Cómo el input del usuario se refleja sin sanitizar

2. Stored XSS

  • Nivel: Principiante-Intermedio
  • Objetivo: Almacenar código malicioso que persista
  • Aprenderás: Impacto de XSS persistente en múltiples usuarios

3. DOM-based XSS

  • Nivel: Intermedio
  • Objetivo: Explotar JavaScript vulnerable del lado del cliente
  • Aprenderás: Cómo el código JavaScript inseguro crea vulnerabilidades

4. Bypass de Filtros

  • Nivel: Intermedio-Avanzado
  • Objetivo: Evadir filtros de seguridad básicos
  • Aprenderás: Por qué las blacklists no son suficientes
⚙️ Tecnologías Utilizadas
  • Backend: FastAPI (Python 3.8+)
  • Base de Datos: SQLite
  • Templates: Jinja2 (con autoescape deshabilitado intencionalmente)
  • Frontend: HTML5, CSS3, JavaScript vanilla

📖 Recursos de Aprendizaje

Conceptos Importantes:

  • XSS (Cross-Site Scripting): Inyección de código JavaScript en páginas web
  • Sanitización: Limpieza de input del usuario para eliminar código malicioso
  • Escape HTML: Convertir caracteres especiales (< > & " ') en entidades HTML
  • Content Security Policy (CSP): Header de seguridad que restringe recursos
  • HTTPOnly Cookies: Cookies no accesibles desde JavaScript

Recursos Externos Recomendados:

  • OWASP XSS Prevention Cheat Sheet
  • PortSwigger Web Security Academy
  • HackTheBox / TryHackMe (plataformas de práctica legal)
  • OWASP Top 10 (lista de vulnerabilidades críticas)
🤝 Directrices de Hacking Ético

Si estás interesado en ciberseguridad, sigue estas reglas:

  • Obtén permiso: NUNCA pruebes en sistemas sin autorización explícita
  • Respeta la ley: El hacking sin permiso es ilegal en prácticamente todos los países
  • Usa laboratorios legales: HackTheBox, TryHackMe, VulnHub, DVWA
  • Reporta responsablemente: Si encuentras una vulnerabilidad real, repórtala al propietario
  • Aprende para defender: El objetivo es proteger sistemas, no dañarlos
  • Mantén la confidencialidad: No compartas vulnerabilidades sin resolver públicamente
🔧 Detalles Técnicos del Laboratorio

Configuraciones Inseguras Intencionales:

# Templates Jinja2 sin autoescape templates.env.autoescape = False # Headers de seguridad deshabilitados X-XSS-Protection: 0 X-Frame-Options: ALLOW # Sin Content Security Policy # (No hay header CSP configurado) # Cookies sin protección # (No hay flags HTTPOnly, Secure, SameSite)

¿Cómo debería configurarse en producción?

# Templates Jinja2 con autoescape templates.env.autoescape = True # Headers de seguridad habilitados X-XSS-Protection: 1; mode=block X-Frame-Options: DENY X-Content-Type-Options: nosniff Content-Security-Policy: default-src 'self' # Cookies seguras Set-Cookie: session=...; HttpOnly; Secure; SameSite=Strict
