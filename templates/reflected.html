🔄 Ejercicio 1: Reflected XSS

Explota una vulnerabilidad de búsqueda que refleja tu input sin sanitizar

📋 Instrucciones

Esta página tiene un buscador de productos vulnerable. Tu objetivo es inyectar código JavaScript que se ejecute cuando se muestre el resultado de la búsqueda.

  • Objetivo: Ejecutar JavaScript usando el campo de búsqueda
  • Tipo: Reflected XSS (no persiste en la base de datos)
  • Vulnerabilidad: El término de búsqueda se refleja directamente en la página sin escape HTML
💡 Payloads Sugeridos

Prueba estos payloads copiándolos en el campo de búsqueda:

<script>alert('XSS Reflected!')</script>
<img src=x onerror=alert('XSS!')>
<svg onload=alert('XSS')>
<body onload=alert('XSS')>

🎓 Explicación Técnica

¿Por qué funciona este ataque?

  • El servidor recibe tu búsqueda y la incluye directamente en el HTML de respuesta
  • No se aplica ningún tipo de escape o sanitización al input del usuario
  • El navegador interpreta tu input como código HTML/JavaScript válido
  • El código se ejecuta en el contexto del dominio vulnerable

Impacto en el mundo real:

  • Robo de cookies de sesión: document.cookie
  • Redireccionamiento a sitios maliciosos
  • Modificación del contenido de la página
  • Captura de teclas (keylogging)
🛡️ ¿Cómo Prevenir Reflected XSS?
  • Escape HTML: Convertir caracteres especiales (< > " ' &)
  • Validación de entrada: Verificar que el input cumple el formato esperado
  • Content Security Policy: Usar headers CSP para bloquear scripts inline
  • Encoding contextual: Aplicar el encoding apropiado según el contexto (HTML, JavaScript, URL)
