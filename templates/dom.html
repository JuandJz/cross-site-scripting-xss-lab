🌐 Ejercicio 3: DOM-based XSS

Explota JavaScript del cliente que manipula el DOM de forma insegura

📋 Instrucciones

Esta página usa JavaScript para leer parámetros de la URL y actualizar el contenido del DOM de forma insegura. La vulnerabilidad está completamente en el lado del cliente.

  • Objetivo: Ejecutar JavaScript manipulando parámetros de URL
  • Tipo: DOM-based XSS (vulnerabilidad en JavaScript del cliente)
  • Vulnerabilidad: JavaScript usa innerHTML con datos no validados
  • Diferencia: El servidor NO procesa el payload, todo ocurre en el navegador
💡 Payloads Sugeridos

🎓 Explicación Técnica

¿Qué hace diferente al DOM-based XSS?

  • Cliente-side: La vulnerabilidad está en JavaScript del navegador, no en el servidor
  • No visible en logs: Los payloads en fragments (#) no se envían al servidor
  • Difícil de detectar: WAFs y filtros del servidor no lo ven
  • Fuentes peligrosas: location.href, location.hash, location.search, document.URL
  • Sumideros peligrosos: innerHTML, document.write, eval, setTimeout

Código vulnerable típico:

// ⚠️ VULNERABLE const name = new URLSearchParams(location.search).get('name'); document.getElementById('welcome').innerHTML = 'Hola ' + name; // ❌ También vulnerable const hash = location.hash.substring(1); document.write(hash);
🛡️ ¿Cómo Prevenir DOM-based XSS?
  • Usar textContent en vez de innerHTML: Inserta como texto, no como HTML
  • Validar input del cliente: Verificar formato antes de usar
  • Evitar eval y similares: No usar eval(), Function(), setTimeout con strings
  • Sanitizar con DOMPurify: Biblioteca especializada para limpiar HTML
  • Content Security Policy: Bloquear inline scripts y eval
  • Trusted Types API: Prevenir asignaciones peligrosas al DOM
